## 1. 项目概述

### 1.1 项目简介

星尘（Stardust）是一个分布式服务平台，提供进程守护、远程部署、性能监控等功能。科控物联版本是基于官方版本进行定制化改造，主要包含以下变更：

| 变更项 | 说明 |
|--------|------|
| 项目信息 | 修改公司名称、项目标题、版权信息 |
| Logo 设计 | 自定义科技感 Logo |
| 服务器地址 | 指向科控物联私有服务器 |
| 部署策略 | 支持 Node.js、Java 等系统命令启动 |
| 安全加固 | 隐藏服务器地址输出 |
| 单文件打包 | ILRepack 合并依赖 DLL |

### 1.2 技术栈

- **核心框架**: .NET 10 / .NET Framework 4.6.1
- **前端框架**: Vue 3 + TypeScript + Vite
- **数据库**: SQLite / MySQL / SQL Server
- **包管理**: NuGet

## 4. Web 管理面板（WebPanel）

### 4.1 访问信息

| 项目 | 值 |
|------|-----|
| 地址 | `http://127.0.0.1:5581/` |
| 用户名 | `admin` |
| 密码 | `admin` |
| 来源 | `NewLife.Agent.WebPanel.AgentWebPanel`（库内置） |

> 💡 WebPanel 是 NewLife.Agent 库内置功能，代码不在 StarAgent 项目中。
> ServiceBase 启动时会自动读取 `Agent.config` 的 `WebPort` 配置并创建 WebPanel。

### 4.2 端口配置

**配置文件**: `Agent.config`（XML 格式）

```xml
<!--Web管理面板端口。默认5581-->
<WebPort>5581</WebPort>
```

> ⚠️ WebPanel 由 ServiceBase（NewLife.Agent）自动创建，读取 `Agent.config` 的 `<WebPort>` 节点。
> 与 `StarAgent.config` 无关。
> 设置为 0 表示禁用 Web 管理面板。

### 4.3 自动配置机制

首次运行时，`Program.cs` 会检测 `NewLife.Agent.Setting.IsNew` 特性，自动设置 WebPort 默认值：

```csharp
var agentConfig = NewLife.Agent.Setting.Current;
if (agentConfig.IsNew)
{
    agentConfig.WebPort = 5581;
    agentConfig.Save();
}
```

**设计说明**:
- ✅ 首次运行时自动生成 `Agent.config`，WebPort 默认为 5581（避免与 ApiServer 的 5580 冲突）
- ✅ 已存在配置文件时不会覆盖用户自定义设置
- ✅ `IsNew` 特性由 NewLife.Configuration 框架提供，当配置文件不存在或首次加载时为 true
- ✅ 使用 NewLife.Agent 库内置的 `Setting` 类，无需自定义配置类
- ⚠️ 必须在 `new MyService()` 之前执行，否则 ServiceBase 构造时会先创建默认配置（5580）

### 4.4 面板功能

- ✅ Agent 状态监控
- ✅ 应用服务管理（启动/停止/重启）
- ✅ 服务列表与运行状态
- ✅ 本地心跳检测

### 4.5 安全说明

> ⚠️ 管理面板默认监听本地回环地址（127.0.0.1），禁止远程访问

## 7. 常见问题

### 7.1 编译错误

**Q**: `IISServerOptions` 类型加载失败
**A**: .NET 10 中该类型已变更，已注释掉 `Stardust.Web/Startup.cs` 中的 IIS 配置

**Q**: ILRepack 打包后缺少 `System.Threading.Tasks.Extensions.dll`
**A**: 已在 `ILRepack.targets` 中添加该 DLL 的打包配置

### 7.2 运行问题

**Q**: 部署 Node.js 应用时报错 193
**A**: 确保已应用部署策略修复，配置 `FileName=node.exe`

**Q**: 发布时提示"未指定目标框架"
**A**: 使用 `-f` 参数指定目标框架：`dotnet publish -f net10.0`

**Q**: WebSocket 异常日志频繁输出
**A**: 已添加 `WebSocketLogFilter` 过滤器屏蔽连接关闭时的正常异常

**Q**: 节点在线页面点击"重启服务"提示"无权操作"
**A**: 已修改服务端权限校验逻辑，`AllowControlNodes` 为空时默认放行

**Q**: StarAgent 重命名后 `node/restart` 命令失效
**A**: 已修改启动逻辑，使用当前进程路径而非硬编码名字

### 7.3 安全问题

**Q**: 管理面板是否支持远程访问
**A**: 默认仅监听 127.0.0.1，如需远程访问需修改代码配置

**补丁 P007**: 在 `Stardust/Managers/NetRuntime.cs` 的 `Download` 方法中，在版本相对地址拼接逻辑之前，添加 BaseUrl 文件 URL 检测：

```csharp
// 如果 BaseUrl 是完整文件地址（以 .exe/.msi/.msu 等结尾），提取目录部分
var baseDir = BaseUrl;
if (!String.IsNullOrEmpty(baseDir))
{
    var lastSegment = baseDir.TrimEnd('/').Substring(baseDir.TrimEnd('/').LastIndexOf('/') + 1);
    if (lastSegment.Contains('.') && !lastSegment.StartsWith("."))
        baseDir = baseDir.TrimEnd('/').Substring(0, baseDir.TrimEnd('/').LastIndexOf('/'));
}
```

然后将后续代码中的 `BaseUrl` 替换为 `baseDir`。

> **根因**：`FrameworkManager.DoInstall` 把命令参数中的 `BaseUrl`（完整文件 URL，如 `.../windowsdesktop-runtime-10.0.10-win-x64.exe`）直接赋给 `NetRuntime.BaseUrl`，而 `Download` 方法假设 BaseUrl 是目录路径，拼接时把版本号和文件名追加到 `.exe` 后面，导致 404。

**补丁 P008**: 使用 NewLife.Agent 源码替换 NuGet 包引用：

1. 从 `https://github.com/NewLifeX/NewLife.Agent` 拉取源码到 `NewLife.Agent.Source/`
2. 将 `StarAgent.csproj` 中的 NuGet 引用改为项目引用：
