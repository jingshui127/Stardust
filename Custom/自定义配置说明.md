## 1. 项目概述

### 1.1 项目简介

星尘（Stardust）是一个分布式服务平台，提供进程守护、远程部署、性能监控等功能。科控物联版本是基于官方版本进行定制化改造，主要包含以下变更：

| 变更项 | 说明 |
|--------|------|
| 项目信息 | 修改公司名称、项目标题、版权信息 |
| Logo 设计 | 自定义科技感 Logo |
| 服务器地址 | 指向科控物联私有服务器 |
| 部署策略 | 支持 Node.js、Java 等系统命令启动 |
| 安全加固 | 隐藏服务器地址输出 |
| 单文件打包 | ILRepack 合并依赖 DLL |

### 1.2 技术栈

- **核心框架**: .NET 10 / .NET Framework 4.6.1
- **前端框架**: Vue 3 + TypeScript + Vite
- **数据库**: SQLite / MySQL / SQL Server
- **包管理**: NuGet

> ServiceBase 的 `CreateWebPanel` 虚拟方法被重写，返回 `StarPanel`，由基类自动管理生命周期。

### 4.2 端口配置

**配置文件**: `Agent.config`（XML 格式）

```xml
<!--Web管理面板端口。默认5580（NewLife.Agent 官方默认值）-->
<WebPort>5580</WebPort>
<!--启用 ServiceBase 自动创建 WebPanel（通过 CreateWebPanel 重写返回 StarPanel）-->
<EnableWebPanel>true</EnableWebPanel>
```

> 💡 `EnableWebPanel=true` 启用 ServiceBase 自动创建流程，`CreateWebPanel` 被重写为返回 `StarPanel`（从上游检出），创建的是官方版面板。
> `WebPort` 由 `AgentWebPanel` 基类构造函数读取，默认 5580（与 ApiServer 的 5500 不冲突）。
> 与 `StarAgent.config` 无关。

### 4.3 启动机制（P017 最终架构 - NuGet 引用 + CreateWebPanel 重写）

首次运行时，`Program.cs` 会检测 `NewLife.Agent.Setting.IsNew` 特性，自动设置 Description：

```csharp
var agentConfig = NewLife.Agent.Setting.Current;
if (agentConfig.IsNew)
{
    agentConfig.Description = "持续监控应用运行状态，自动重启崩溃服务.科控物联QQ：2492123056";
    agentConfig.Save();
}
else if (!agentConfig.EnableWebPanel)
{
    // 旧版本可能禁用了 WebPanel，重新启用以使用 CreateWebPanel 继承版
    agentConfig.EnableWebPanel = true;
    agentConfig.Save();
}
```

`MyService` 重写 `CreateWebPanel` 虚拟方法，基类 `ServiceBase.StartWork()` 会自动调用：

```csharp
protected override AgentWebPanel CreateWebPanel(ServiceBase service)
{
    // 返回 StarPanel（从上游 NewLifeX/Stardust 检出），重写 EmbeddedResourcePrefix/RegisterRoutes
    return new StarAgent.WebPanel.StarPanel(service);
}
```

**设计说明**:
- ✅ 首次运行时自动生成 `Agent.config`，WebPort 采用官方默认 5580（与 ApiServer 的 5500 不冲突）
- ✅ `EnableWebPanel=true` 启用基类自动创建流程，`CreateWebPanel` 重写返回 `StarPanel`
- ✅ 旧版本升级时自动修正 `EnableWebPanel` 为 true（从源码模式迁移）
- ✅ Web 面板由 `ServiceBase` 基类自动管理生命周期（创建/启动/停止），无需手动干预
- ✅ `StarPanel` 继承 `AgentWebPanel`，复用官方完整功能（状态/控制/日志/健康检查/子服务管理/星尘配置/本机信息）
- ✅ 官方 `StarApi` 直接提供子服务管理（`Services`/`StartService`/`StopService`/`RestartService`/`AddService`/`RemoveService`）、星尘配置（`GetStarConfig`/`UpdateStarConfig`）、本机信息（`Machine`/`GetProcessList`）API

### 4.4 官方 5 个虚拟扩展点（commit 9d0b78bd）

NewLife.Agent `10.16.2026.716-beta1245+` 新增了 5 个 `protected virtual` 扩展点，允许子类定制 WebPanel 行为而无需修改源码：

| 扩展点 | 所在类 | 返回类型 | StarPanel 重写内容 |
|--------|--------|----------|---------------------|
| `CreateWebPanel(ServiceBase)` | `ServiceBase` | `AgentWebPanel` | 返回 `new StarPanel(service)`（从上游检出） |
| `EmbeddedResourcePrefix` | `AgentWebPanel` | `String` | 返回 `"StarAgent.WebPanel.wwwroot"`（指向 StarAgent 的嵌入式资源） |
| `EmbeddedResourceAssemblyType` | `AgentWebPanel` | `Type` | 返回 `typeof(StarPanel)`（标记资源所在程序集） |
| `RegisterRoutes()` | `AgentWebPanel` | `void` | 先注册 `StarApi` 控制器（`/star`），再调用 `base.RegisterRoutes()` |
| `GetExtensions()` | `AgentWebPanel` | `List<PanelExtension>` | 未重写（官方 `StarApi` 提供所有功能，无需扩展面板） |

### 4.6 路由设计（重要）

#### 4.6.1 路由前缀选择

| 路由前缀 | 控制器 | 方法示例 |
|----------|--------|----------|
| `/api` | 官方 `ApiController`（基类注册） | `/api/login`, `/api/status`, `/api/control`, `/api/configMetadata` |
| `/star` | `StarApi`（自定义注册） | `/star/services`, `/star/getStarConfig`, `/star/updateStarConfig`, `/star/machine` |
| `/*` | 嵌入式静态资源（基类注册） | `/index.html`, `/favicon.ico` |

> ⚠️ **必须使用单段前缀 `/star`**，不能用多段前缀如 `/api/star`。
> 原因：`NewLife.Http.ControllerHandler.ProcessRequest` 按 `/` 拆分路径并**固定取 `ss[2]`**（第 3 段）作为方法名。
> `/star/services` → `ss = ["", "star", "services"]` → `ss[2]="services"` ✅
> `/api/star/services` → `ss = ["", "api", "star", "services"]` → `ss[2]="star"` ❌ 方法找不到

#### 4.6.2 路由注册顺序（关键）

`RegisterRoutes()` 中**必须先注册自定义控制器，再调用 `base.RegisterRoutes()`**：

```csharp
protected override void RegisterRoutes()
{
    // 1. 先注册 /star/* 自定义控制器（StarApi，继承 IHttpController）
    Server.MapController<StarApi>("/star");
    // 2. 再调用基类注册 /api（官方 ApiController）和 /*（嵌入式资源通配符）
    base.RegisterRoutes();
}
```

> ⚠️ 如果先调用 `base.RegisterRoutes()`，`/*` 通配符会先匹配 `/star/*`，导致所有自定义 API 返回 404。

### 6.5 上游同步工作流（整体解决方案策略）

> 💡 **设计决策**：解决方案 `星尘.sln` 中的 12 个项目**统一保持源码引用**（只有 `StarAgent` 因单文件打包需求改用 NuGet）。
> **理由**：`Stardust.Server` 含 P002 补丁（`NodeService.cs` 的 `AllowControlNodes` 权限校验）必须源码引用；既然服务端必须源码，整个解决方案统一源码引用可避免"源码+NuGet 混用"的版本不一致问题，也保留了跨项目断点调试能力。

#### 6.5.1 项目引用方式分类

| 项目 | 引用方式 | 说明 |
|------|----------|------|
| `Stardust` | 源码引用（ProjectReference） | 核心库，被其他项目引用 |
| `Stardust.Data` | 源码引用 | XCode 数据实体层 |
| `Stardust.Server` | 源码引用 | ⚠️ 含 **P002 补丁**，不可用 NuGet 替代 |
| `Stardust.Web` | 源码引用 | 依赖 `Stardust.Server` 源码 |
| `Stardust.Extensions` | 源码引用 | 服务端扩展库 |
| `StarGateway` / `DeployAgent` / `StarAgentTool` | 源码引用 | 独立应用，调试方便 |

## 7. 常见问题

### 7.1 编译错误

**Q**: `IISServerOptions` 类型加载失败
**A**: .NET 10 中该类型已变更，已注释掉 `Stardust.Web/Startup.cs` 中的 IIS 配置

**Q**: ILRepack 打包后缺少 `System.Threading.Tasks.Extensions.dll`
**A**: 已在 `ILRepack.targets` 中添加该 DLL 的打包配置

### 7.2 运行问题

**Q**: 部署 Node.js 应用时报错 193
**A**: 确保已应用部署策略修复，配置 `FileName=node.exe`

**Q**: 发布时提示"未指定目标框架"
**A**: 使用 `-f` 参数指定目标框架：`dotnet publish -f net10.0`

**Q**: WebSocket 异常日志频繁输出
**A**: 已添加 `WebSocketLogFilter` 过滤器屏蔽连接关闭时的正常异常

**Q**: 节点在线页面点击"重启服务"提示"无权操作"
**A**: 官方已添加 `AllowControlNodesWhenEmpty` 全局开关（commit f3240480）。本地 `Stardust.Server/Setting.cs` 默认值改为 `true`（内部环境兼容）。如生产环境需安全模式，设置为 `false`。

**Q**: StarAgent 重命名后 `node/restart` 命令失效
**A**: 官方已修复（commit 503cff22），使用 `GetExecutableName()` 动态获取进程名。

**Q**: WebPanel 无法启动，端口冲突
**A**: 检查 `Setting.cs` 中 `LocalPort` 是否为 5500（官方默认）。如被改成 5580 会与 WebPort 5580 冲突。

**Q**: Linux 无 WiFi 设备时频繁输出 "command failed: No such device (-19)"
**A**: 官方已修复（commit 9285c877），动态检测 WiFi 接口。如仍有问题，检查 NuGet 包版本是否 ≥ `3.9.2026.720-beta1136`。

### 7.3 安全问题

**Q**: 管理面板是否支持远程访问
**A**: 默认仅监听 127.0.0.1，如需远程访问需修改代码配置
